# Contributing to CodeTrace

Thank you for your interest in contributing to CodeTrace! 🎉

## 🚀 Getting Started

1. **Fork** the repo and clone it locally
2. Run `npm install` to install dependencies
3. Create a `.env` file based on `.env.example`
4. Run `npm run dev` to start the development server

## 📋 Development Guidelines

### Code Style
- Use **TypeScript** for all new code
- Follow the existing component patterns in `src/frontend/components/`
- Use **Tailwind CSS** for styling — no inline styles
- Prefer **Framer Motion** for animations

### Commit Messages
We follow [Conventional Commits](https://www.conventionalcommits.org/):
- `feat:` — New feature
- `fix:` — Bug fix
- `docs:` — Documentation changes
- `style:` — Code style changes (formatting, etc.)
- `refactor:` — Code refactoring
- `perf:` — Performance improvements
- `test:` — Adding or updating tests

### Pull Requests
1. Create a feature branch from `master`
2. Make your changes with clear, descriptive commits
3. Ensure the app builds without errors (`npm run build`)
4. Open a PR with a clear description of what changed and why

## 🐛 Reporting Bugs

Open an [issue](https://github.com/Satya522/CodeTrace/issues) with:
- A clear title and description
- Steps to reproduce
- Expected vs actual behavior
- Screenshots if applicable

## 💡 Feature Requests

We love new ideas! Open an [issue](https://github.com/Satya522/CodeTrace/issues) with the `enhancement` label.

## 📜 Code of Conduct

Be respectful, inclusive, and constructive. We're all here to learn and build together.

Thank you for helping make CodeTrace better! ❤️

## 🌍 The Open Source Vision

CodeTrace started as an internal tool to help engineers visualize complex algorithms, but we quickly realized its potential for the entire developer community. By open-sourcing our core visualizer engine, we aim to make high-level algorithmic execution accessible and understandable for everyone.

> *"We don't just want you to use CodeTrace. We want you to help us build it."*

---

## 🛠️ The Tech Stack

Our platform is engineered for absolute performance and low latency. Here is what powers the engine under the hood:

| Layer | Technologies | Purpose |
| :--- | :--- | :--- |
| **Frontend Framework** | `Next.js 14`, `React 18` | Server-Side Rendering & Routing |
| **Styling & UI** | `Tailwind CSS`, `Framer Motion` | Glassmorphic UI & 60FPS Animations |
| **Code Editor** | `Monaco Editor` | Rich IntelliSense & Syntax Highlighting |
| **AST Parser** | `Acorn` / `Babel` | Tokenizing & Instrumenting raw code |
| **Execution Sandbox** | `Isolated-VM` (V8) | Secure, ephemeral code execution |
| **Visualizer** | `Canvas API`, `Mermaid` | Rendering the memory graph & stack |

## 🤝 How to Contribute

We welcome contributions of all sizes! Whether you are fixing a typo in our docs or rewriting our WebGL rendering pipeline, your help is appreciated.

### 1. Beginner Issues (Good First Issues)
If you are new to open source, look for the `good first issue` label on our repository. These are typically:
- CSS bug fixes (e.g., responsive alignment issues).
- Adding new algorithm examples to our templates.
- Improving test coverage.

### 2. Core Engine Contributions
If you are an advanced engineer, we always need help optimizing the AST compiler and the V8 sandbox bridge. Look for the `core-engine` label.

---

## 📜 Contribution Guidelines

Before submitting a Pull Request, please ensure you follow our standards:
1. **Fork the Repo:** Clone the repository locally.
2. **Branch Naming:** Use `feature/<name>` or `bugfix/<name>`.
3. **Tests:** Run `npm run test` to ensure you haven't broken the execution sandbox.
4. **Linting:** We strictly enforce Prettier and ESLint. Run `npm run lint` before committing.
5. **PR Description:** Include screenshots or screen recordings if you modified the UI.
